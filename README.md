絵はカップの上に貼りつけてあるのではありません。**手描きの絵をいったん
「ミルクの濃さ」に変換し、上から注がれる液体としてシミュレーションに載せています。**
だから指でなぞると、本物のように混ざって崩れます。

画面いっぱいの 1 杯を先頭に置き、その下に 4 杯を 右→左→右→左 のジグザグに並べました。
いちばん下の杯では、自分で描いたり、手持ちの画像を注いだりできます。

素の HTML / CSS / JavaScript だけで動きます。**ビルド作業は不要**で、
`index.html` をダブルクリックすれば開きます。

技術的に手こずった点は [3. 流体のしくみ](#3-流体のしくみ) の
「つまずきやすいところ」にまとめました。

> **BGM について** — 音源は再配布の可否が確認できていないため、このリポジトリには
> 含めていません（`.gitignore` で除外）。`bgm.mp3` を置かなければ BGM の区画ごと
> 表示されないので、無くてもそのまま動きます。

## 1. 動く条件

- **WebGL2** と **EXT_color_buffer_float**（浮動小数点テクスチャ）が必要です。
  2020 年以降のブラウザならほぼ動きます。
- 使えない環境では、カップの代わりに理由を書いたメッセージが出ます（真っ黒にはなりません）。
- ライブラリは一切使っていません。Google Fonts 以外は外部から何も読み込みません。

## 2. ラテアートの作りかた



<img width="1128" height="624" alt="スクリーンショット 2026-10-05 140540" src="https://github.com/user-attachments/assets/46a331cc-fd18-4d03-9582-03a9a84be930" />



いま表示されている 4 杯の絵は、**すべて手で描いたものです。**
紙やお絵かきアプリで描いた絵を `makeart.py` に通して「型」に焼き、
`index.html` の `data-art` から指しています。

| 杯 | 型 |
| --- | --- |
| 見出しの大きなカップ | `art/a.png` |
| 01 リーフ | `art/c.png` |
| 02 白鳥 | `art/b.png` |
| 03 ハートリーフ | `art/d.png` |

### 絵を「型」に焼く

型とは **768×768 の白黒 PNG** で、白がミルク、黒がコーヒーを表します。
これを作るのが `makeart.py` です。

```
python makeart.py 手描き.jpg art/a.png
python makeart.py 手描き.jpg art/a.png --invert   # 白と黒が逆のとき
```

やっていることは 3 つだけです。

1. **絵と紙を分ける** — 透明を持つ PNG なら、透明度をそのままミルクの濃さに使う。
   持たない画像は輝度を **大津の二値化**（`otsu()`）でしきい分けし、
   画像のふちの平均輝度を「紙」とみなして、その反対側を絵とする。
   境目は 14 階調ぶんぼかすので、輪郭がギザギザになりません。
2. **絵のある四角を切り出す** — 写真の余白を捨てます。
   全面が同じ色に見えるとき（濃さの平均が 93% 超、または 0.2% 未満）は
   エラーにして、白黒の反転をうながします。
3. **カップの内側いっぱいに置き直す** — 直径の 86% に収まるよう中央へ。
   カップの直径はピクセルで `(CUP_R / SIM_HALF) * 768`（= 0.696 × 768）です。

**白い紙に黒いペンで描いた絵なら、反転オプションは要りません。**
`makeart.py` は画像のふちを「紙」とみなすので、黒で描いた線がそのまま
ミルク（白）として扱われます。

### 焼いた型を杯に結びつける

canvas に `data-art="art/a.png"` と書くと、その杯の絵になります。
同じパスを指した杯は同じ絵になります。
**読み込めなかったときは、後述する組み込みの図形がそのまま残る**ので、
型を用意するまでサイトが壊れることはありません。

焼いた型は `FRAG_MASK_PHOTO` がカップの形に切り抜いて `mask` テクスチャへ描き込み、
そこから上から下へ注がれていきます。

### 訪れた人も絵を入れられる

いちばん下「自分で描く」の杯だけ、手持ちの画像を注げます（カップへドラッグしても入ります）。
**処理は `makeart.py` とまったく同じ手順**を、ブラウザの中の `buildMask()` が走らせているだけです。
**画像はどこにも送信されません。**

結果は `localStorage`（キー `latte-art-breaker/drawing/me`）に 384×384 で覚えるので、
開き直しても残ります。「まっさらにする」で消えます。

### 組み込みの図形（型が無いときの受け皿）

`data-art` を書かない、あるいは型が読み込めなかった杯では、
`data-pattern` に応じた図形を**数式で**描きます。手描きに差し替える前は、
こちらが本番の絵でした。

本物のラテアートは、ピッチャーを振るたびに置かれた泡の弧が次の弧に覆われ、
「外側だけが残る」ことで層になります。写真をよく見ると、白い三日月が何枚も
重なっているのが数えられます。その構造をそのまま実装したものです。

- `lune()` — 三日月ひとつ。`(±W, 0)` を通る 2 本の円弧に挟まれた領域です。
  2 本とも同じ 2 点を通るので、**両端が必ず尖ります**。これが葉先の鋭さになります。
- `rosetta()` — `lune()` を根元から先端へ積み上げます。幅は釣鐘状に増減させ、
  白の厚みを間隔の 74% にすることで、残りがクレマの細い筋として見えます。
- **`sweep`（反り）** — 本物は注いだ線がカップの中の流れに巻き込まれ、葉先が
  根元側へ寄ります（"the lines follow the flow of the cup and wrap around"）。
  三日月を評価する前に `y += sweep * x * x` を掛けると、葉先ほど下がった
  弓なりの葉になります。曲線の美しさはここで出ています。

引数は `rosetta(p, yA, yB, Wmax, N, bulge, sweep, stemOn)` です。
`N` が葉の枚数（資料では「振り 1 回につき葉 1 枚」）、`bulge` がふくらみ具合、
`stemOn` は中央を貫く引き抜きの有無です。

| 関数 | 形 |
| --- | --- |
| `fRosetta()` | リーフ（ロゼッタ） |
| `fSwan()` | 白鳥。羽は `rosetta()`（茎なし）＋脇を通る引き抜き＋ハートの頭 |
| `fWingHeart()` | ハートリーフ。ハートの輪郭＋内側に小さな `rosetta()` |
| `heartF()` | ハートの陰関数（輪郭づくりに使用） |

白鳥は資料に沿って組んであります。羽はロゼッタですが、
**引き抜きを羽の中央ではなく「脇」に沿わせる**のがポイントで
（"instead of running the milk through the middle of the rosetta waves,
pull the milk along side the rosetta"）、その線がそのまま首になり、
最後に置く**ハートが頭**になります（"create a heart shape - the head of the swan"）。
ハートのとがりが、そのままくちばしです。

型でも数式でも、**できあがった絵は同じ `mask` テクスチャに入ります**。
評価が重いので**注ぎ直したときに一度だけ**焼いており、
関数を複雑にしても表示は遅くなりません。

カップ・受け皿・持ち手・ティースプーン・角砂糖は、これとは別に
`FRAG_RENDER` の中の距離関数で毎フレーム描いています。

### 自分で描く（いちばん下の杯）



<img width="1146" height="765" alt="スクリーンショット 2026-10-05 140716" src="https://github.com/user-attachments/assets/944c3cd6-2d25-4ba0-a9db-9df1bb71af8f" />



この杯だけは作りが違います。型を焼くのではなく、
**注ぎ口をそのまま指に繋いだ流体ストローク**（`FRAG_STROKE`）で、

1. 指のまわりの液を外へ押しのける（上から液が落ちる分、面積は保存しない）
2. 進行方向へ引きずる
3. そこへ新しいミルクを置く

を毎フレーム繰り返します。`data-pattern="-1"` の杯がこれになります。
「消す」は同じシェーダを `uInk = -1` で走らせているだけです。
画像を注いだあとに、その上から指で描き足すこともできます。

## 3. 流体のしくみ

いわゆる **Stable Fluids**（Jos Stam）の流れをそのまま GPU に乗せたものです。

1. **速度の移流** — いまの速度を、その速度に沿って前のコマから拾い直す。同時に、
   指が触れているところの速度をポインタの速度に寄せる。
2. **発散を計算** — 各点で液体が湧き出している／吸い込まれている量を測る。
3. **圧力を解く** — 発散を打ち消す圧力をヤコビ法で 24 回反復して求める。ここが一番重い。
4. **圧力の勾配を引く** — 体積が保たれる（非圧縮の）流れになる。
5. **ミルク濃度の移流** — できた流れにミルクの濃度を乗せて運ぶ。
6. **描画** — 濃度 1 が泡、0 がクレマ、中間はカフェオレ色（抹茶なら薄緑）。

**計算が回るのは、触れている間とその直後だけです。** 指を離すと約 1.6 秒かけて
流れが収まり、そのあとは計算そのものを止めます（`CONF.SETTLE`）。
放っておいても模様は崩れません。5 杯並んでいても、触っていない杯は描画だけです。

さらに `IntersectionObserver` で、画面に入っていない杯は描画も止めています。

### つまずきやすいところ

- **手順 4 を省くと破綻します。** 圧力投影をしないと流れが非圧縮になりません。
  すると白い部分の面積がどんどん増えて、数秒でカップが真っ白になります。
- **「模様の座標」を運ぶ方式はうまくいきません。** 元絵のどこを参照するかという座標を
  移流させると、双線形補間の数値拡散で座標が平均値へ収縮します。運ぶのは座標ではなく
  **濃度**にしてください。
- 力の加え方も注意が必要です。毎フレーム力を**足し込む**と速度が発散します。
  ポインタの速度へ `mix()` で**寄せる**方式にすると安定します（`FRAG_VEL`）。

## 4. いじりかた

### 杯を増やす・入れ替える

`index.html` の `<section class="stage">` を足すだけです。`data-` 属性で中身が決まります。

| 属性 | 意味 |
| --- | --- |
| `data-cup` | この canvas を 1 杯として扱う（値は不要） |
| `data-art` | 表示する型のパス（`makeart.py` で焼いた白黒 PNG） |
| `data-pattern` | 型が無い／読めないときに描く図形。`0`=リーフ / `1`=白鳥 / `2`=ハートリーフ / `-1`=まっさら（自分で描く） |
| `data-hero` | `1` で画面いっぱいの見出し用になる（横長のときカップが右へ寄る） |
| `data-matcha` | `1` で抹茶ラテの色になる |
| `data-spoon` | `1` でティースプーンを置く |
| `data-sugar` | `1` で角砂糖を置く |
| `data-slot` | 訪れた人が入れた絵の置き場の名前。同じ名前の杯は同じ絵を共有する |

`data-art` のパスには `?v=5` のような文字列を付けてあります。
**絵を差し替えたときに、ブラウザが古い画像を使い続けないようにするため**です。
差し替えたら、この数字をひとつ上げてください。

訪れた人が画像を入れられるようにするには、その `<section>` に `data-slot` を付け、
中に `class="mine"` の一式（`[data-photo]` のファイル入力、`[data-photo-invert]`、
`[data-photo-note]`）を置きます。`[data-act="clear"]` のボタンがあれば、
それが入れた絵も一緒に消します。

`class="stage stage--flip"` を付けるとカップが左に来ます。
**右→左→右** になるよう、1 つおきに付けてください。

### 触り心地を変える

`latte.js` の先頭にある `CONF` が全部の設定です。

| 項目 | 既定値 | 意味 | 効果 |
| --- | --- | --- | --- |
| `RADIUS` | 0.060 | かき混ぜる筆の太さ | 大きいほど広い範囲が動く |
| `DECAY` | 0.988 | 速度の減衰 | 1 に近いほど渦が長く残る |
| `DECAY_IDLE` | 0.90 | 手を離した後の減衰 | 小さいほど早く静止する |
| `SETTLE` | 1.6 | 静止までの秒数 | 0 にすると触った瞬間しか動かない |
| `DRAG` / `HOVER` | 0.90 / 0.32 | 力の強さ | ドラッグ時／ホバー時 |
| `NEED` | 1.43 | 画面に必ず収める半径 | 大きくすると全体が引きで映る |
| `ITERS` | 24 | 圧力ソルバの反復回数 | 減らすと軽くなるが渦が崩れる |
| `ND` | 768 | ミルク濃度の解像度 | 下げると軽くなるが模様が粗くなる |

画面下のバーにある「混ざりやすさ」「ゆるさ」「湯気」は、**すべての杯に同時に効きます**。
範囲は `index.html` 側で決めています（混ざりやすさ 0.9〜1.6、ゆるさ 0.05〜0.475）。
中身はそれぞれ `shared.strength`（指の力）と `shared.visc`（速度場の平滑化＝粘性）です。

つまみの位置は `paintRanges()` が CSS 変数 `--p`（0〜100）に入れ、`style.css` が
そこまでを色で塗ります。バーの説明文は `index.html` の `.guide` にあります。

### BGM を鳴らす

`bgm.mp3`（または `bgm.m4a` / `bgm.ogg`）をこのフォルダに置くと、
つまみの説明のすぐ下に **🎺 のボタン**が出ます（`index.html` の `.jazz`）。
ファイルが無いときは、その区画ごと出ません。

音量は `latte.js` の `bindBgm()` の中の `audio.volume = 0.35;` で変えられます。
ブラウザは音の出る自動再生を禁止しているので、**必ずボタンを押してからの再生**にしてあります。

### 色を変える

- ページ全体の色 … `style.css` の先頭 `:root`
- 液体の色 … `latte.js` の `FRAG_RENDER` の `baseLit` / `baseDark` / `midCol` / `foam`
  （`uMatcha` でコーヒーと抹茶を混ぜ分けています）
- 小物の位置 … 同じく `FRAG_RENDER` の `SUGAR_A` / `SUGAR_B` / `SPOON_B` / `SPOON_E` / `SAUCER_R`

## 5. 重いとき

5 杯ぶんの WebGL コンテキストが動くので、古い GPU では負荷が上がります。
`CONF` を次のように下げると、かなり軽くなります。

```js
NV:    192,   // 256 から
ND:    512,   // 768 から
ITERS: 16,    // 24 から
```

画面幅が狭いときは `ND` が自動で 512 に落ちます。

## 6. 公開するとき

このフォルダの中身をまるごとアップロードすれば動きます
（S3 / Netlify / GitHub Pages / 普通のレンタルサーバー、どれでも）。
ビルドもサーバー側の設定も要りません。

S3 に置くときだけ、`.js` `.css` `.png` `.mp3` の **Content-Type** を明示してください。
省くと `application/octet-stream` になり、ブラウザが読み込みを拒否します。

```
aws s3 cp index.html s3://<バケット>/index.html --content-type "text/html; charset=utf-8" --cache-control "no-cache"
aws s3 cp style.css  s3://<バケット>/style.css  --content-type "text/css; charset=utf-8"
aws s3 cp latte.js   s3://<バケット>/latte.js   --content-type "text/javascript; charset=utf-8"
aws s3 cp art/       s3://<バケット>/art/ --recursive --content-type "image/png" --cache-control "no-cache"
aws s3 cp bgm.mp3    s3://<バケット>/bgm.mp3    --content-type "audio/mpeg"
```

型の PNG には `no-cache` を付けておくことをおすすめします。
長いキャッシュを指定すると、絵を差し替えてもブラウザが取りに来ません。
