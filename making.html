MAKING OF

このサイトは、どうやって作られたのか

サイトを配っているのは S3 バケット 1 つだけで、流体の計算は全部ブラウザの GPU で走ります。 あとから足した「みんなのラテアート」の投稿だけ、Lambda と DynamoDB を使っています。 常時動いているサーバーは、いまも 1 台もありません。

  • リージョン ap-northeast-1
  • 公開ファイル 14 点 / 約 7.0 MB
  • ビルド工程 なし
  • HTTP 実測 2026-10-20

REST エンドポイント 人に見せるならこちら

https://latte-art-breaker-ed645a8f.s3.ap-northeast-1.amazonaws.com/index.html

  • HTTPS が使える。鍵マークが付くので、ブラウザが警告を出しません
  • ルートは開けない。/ を叩くと 403 が返るため、/index.html まで必要
  • 全ファイル実測で 200。Content-Type も意図どおり

ウェブサイトエンドポイント 自分で開くとき

http://latte-art-breaker-ed645a8f.s3-website-ap-northeast-1.amazonaws.com/

  • ルートでトップが開く。静的ウェブサイトホスティングが index.html を返します
  • HTTPS では繋がらない。証明書が無いため、https:// を付けると接続そのものが失敗します
  • 短いので、自分で開く分にはこちらが楽

作ったあとに作り変えたところ

模様は数式から手描きへ最初は三日月を積み上げる距離関数でラテアートを描いていました。 いまは手描きの絵を makeart.py で 768×768 の白黒の「型」に焼き、data-art で杯に結びつけています。 数式版の関数は残してあり、型が読めなかったときの受け皿になります。

絵と紙の見分けかた透明つき PNG は透明度をそのまま使います。 持たない画像は輝度を大津の二値化でしきい分けし、画像のふちを「紙」とみなして反対側を絵とします。 だから白い紙に黒で描いても、反転指定は要りません。

訪れた人も絵を入れられるいちばん下の杯だけ、手持ちの画像を注げます。 処理は makeart.py と同じ手順をブラウザの中で走らせているだけで、 画像はどこにも送信されません。localStorage に残るので開き直しても消えません。

キャッシュで 3 回つまずいた絵の PNG に max-age=86400 を付けたため、 差し替えてもブラウザが取りに来ませんでした。いまは no-cache にし、 ?v= を付けて URL 自体を変えています。

見た目の作り直し細い枠線・半透明のすりガラス・システムのフォントという組み合わせをやめ、 べた塗り＋ずらした硬い影＋丸ゴシックに揃えました。下のつまみも、彫った溝と角砂糖のつまみに作り替えています。

目で見ずに確かめる制作中は画面を見られないので、 ヘッドレスのブラウザで gl.readPixels を叩いて絵柄を文字に起こし、 要素の座標を実測して重なりや折り返しを確認しています。このページの数字も、すべて実ファイルから測ったものです。

みんなのラテアートを足した描いた一杯を投稿して、ほかの人に崩してもらえるようにしました。 ここだけ置き場が要るので、Lambda 1 つと DynamoDB 1 テーブルを足しています。 常時動くものは無いので、誰も遊ばない月は 0 円のままです。

名前は付けない投稿に紐づくのは絵と日付だけにしました。 名前欄を置くと、そこに何を書かれるか管理しきれません。 自分の投稿だけは消せるよう、投稿時に取り消し札を 1 回だけ返し、端末側に持たせています。 サーバーには札そのものではなく、潰した形でしか残していません。

一覧は動かない画像にしたブラウザが同時に持てる WebGL は 8〜16 個ほどしかなく、 全部を動くカップにすると数十件で破綻します。並ぶのは PNG で、動くのは選んだ 1 杯だけにしました。

403 で半日止まったFunction URL を公開にしたのに、呼ぶと 403 が返り続けました。 2025 年 10 月から、lambda:InvokeFunctionUrl と lambda:InvokeFunction の 両方の許可が要る仕様に変わっていたためです。関数を直接呼ぶと動くのに URL だと落ちる、で切り分けました。

許可ヘッダーが 2 つ並んでいたCORS を Lambda のコードと Function URL の設定の両方で付けていたため、 access-control-allow-origin が 2 行返り、ブラウザが無効と判断していました。 curl -D - で応答ヘッダーを数えて気づき、コード側を外しています。

この構成について確認できていること

費用はほぼゼロCost Explorer の実測で 8 月 0.0000000006 USD、9 月 1〜10 日 -0.0000000002 USD。無料枠の中です（2026-09-09 時点）。

CloudFront は入れていない入れれば「短い URL ＋ HTTPS」が両立し、圧縮も効きます。代わりに配信開始まで 5〜15 分かかります。

バケットは読み取り専用で公開バケットポリシーは s3:GetObject の 1 文だけ。匿名での PUT／DELETE／一覧取得は、実際に叩いて 3 つとも 403 を確認しました（2026-10-01）。

ページは鍵を持ちませんJavaScript に認証情報は 1 つも書いていません。ブラウザが外に出すのは、みんなのラテアートの fetch だけです。宛先は config.js に書いた URL 1 本で、鍵を添えずに呼びます。できることは Lambda 側が決めていて、ブラウザからは投稿・一覧・いいね・自分の取り消ししか頼めません。

投稿の受け口は絞ってあるLambda に持たせた役割が触れるのは、投稿を入れる 1 テーブルだけ。他の AWS の資源には手が届きません。同時に動く本数も 5 までにしてあるので、呼ばれ続けても請求は頭打ちになります。

ブラウザ側の必要条件WebGL2 と EXT_color_buffer_float。無い環境では、カップの代わりに理由を書いた文が出ます。

更新は数行aws s3 cp を並べるだけ。index.html は no-cache なので、置いた瞬間から反映されます。

重いのは音源約 7.0 MB のうち 5.92 MB が bgm.mp3、0.71 MB が構成図の PNG、0.24 MB が手描きの型 4 点。残り全部を足しても 0.15 MB しかありません。preload="metadata" なので、開いた時点では音源の本体を落としません。構成図の PNG は 3 倍で撮っていたのを 2 倍にし、256 色に減らして 1.34 MB から 0.71 MB に落としました。元画像との画素のずれは平均 0.1／255 で、文字の明暗幅は変わっていません。

HTTP の応答・サイズ・Content-Type は 2026-10-20 に curl と aws s3api head-object で実測。 費用は 2026-09-09 時点の AWS Cost Explorer の値で、みんなのラテアートを足す前のものです。
